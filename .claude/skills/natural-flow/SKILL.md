# 문단을 자연스럽게 잇기

항목을 늘어놓은 글을 앞뒤가 이어지는 문단으로 고칩니다. 사실은 그대로 두고, 사실을 늘어놓는 순서와 잇는 말, 낱말의 무게만 바꿉니다.

`korean-writing`과 함께 씁니다. 이 스킬로 문단의 흐름을 먼저 잡고, 마지막에 `korean-writing`의 점검표로 문장을 다듬습니다.

## 작업 순서

1. **원본의 사실을 뽑습니다.** 근무처, 기간, 한 일, 쓴 기술, 숫자를 목록으로 적습니다. 다시 쓴 글에는 이 목록에 있는 사실만 들어갑니다.
2. **한 문장으로 말해 봅니다.** 문단마다 "그래서 무슨 얘기인가"를 한 문장으로 적습니다. 이 문장이 안 나오면 문단을 나누거나 합칩니다.
3. **말하는 순서로 다시 배열합니다.** 아래 "흐름"의 원칙에 맞춰 문장 순서를 바꾸고 잇는 말을 넣습니다.
4. **낱말을 가볍게 바꿉니다.** 아래 "낱말" 표를 적용합니다.
5. **사실을 대조합니다.** 1단계 목록과 비교해 빠진 사실, 새로 생긴 사실이 없는지 확인합니다.

## 흐름

- **시간이나 이유의 순서로 잇습니다.** "A했습니다. B했습니다. C했습니다."처럼 같은 무게로 나열하지 않고, "A하다가 B를 하게 됐고, 지금은 C를 합니다"처럼 앞뒤가 이어지게 씁니다.
- **잇는 말을 아껴 씁니다.** "그 전에는", "지금은", "그래서", "덕분에"처럼 실제 관계를 보여 주는 말만 씁니다. "또한", "아울러", "더불어"는 거의 쓰지 않습니다.
- **문장 길이를 섞습니다.** 긴 문장 뒤에는 짧은 문장을 둡니다. 같은 길이, 같은 어미가 세 번 넘게 이어지면 하나를 바꿉니다.
- **주어를 사람으로 둡니다.** "기능은 ~를 제공합니다"보다 "학습자가 ~를 볼 수 있습니다", "구성원이 ~를 확인합니다"처럼 그 기능을 쓰는 사람을 주어로 씁니다.
- **나열은 목록이 맡습니다.** 문단 안에서 쉼표로 다섯 개 넘게 늘어놓지 않습니다. 길게 나열할 내용은 표나 태그로 넘기고, 문단에는 대표가 되는 것만 남깁니다.

## 낱말

공문서나 보고서에서 쓰는 무거운 말을 평소에 말하는 낱말로 바꿉니다. 뜻이 달라지면 바꾸지 않습니다.

| 무거운 말 | 가벼운 말 |
| --- | --- |
| 의복 | 옷 |
| 구현했습니다, 개발했습니다 (매 문장) | 만들었습니다 (번갈아 씀) |
| 확인할 수 있게 했습니다 | 볼 수 있습니다 |
| ~를 바탕으로 | ~로, ~를 가지고 |
| 진행 상황 | 어디까지 했는지 |
| 단기 근무했습니다 | 짧게 일했습니다 |
| 병행하며 | ~하면서 |
| 분야에서 일하고 싶습니다 | ~ 일을 하고 싶습니다 |

업계에서 쓰는 정확한 용어(혼용률, 실측, 상하차, SCM, QA, API)는 그대로 둡니다. 가볍게 바꾸면 오히려 뜻이 흐려집니다.

## 지키는 선

- **지어내지 않습니다.** 원본에 없는 동기, 감정, 깨달음, 성과("고객 만족도를 높였습니다", "그때 개발의 재미를 알았습니다")를 넣지 않습니다. 이야기처럼 이으려다 사실을 만들기 쉬우니 5단계 대조를 빼먹지 않습니다.
- **문체는 합니다체를 유지합니다.** 자연스럽게 쓴다고 해요체나 반말로 바꾸지 않습니다. 1인칭 주어("저는")는 문단 첫 문장에서도 되도록 생략합니다.
- **표와 UI 문구는 건드리지 않습니다.** 표 칸, 버튼, 태그는 `korean-writing`의 명사형 규칙을 따릅니다. 이 스킬은 문단으로 된 글에만 씁니다.
- **분량을 크게 늘리지 않습니다.** 인쇄본이 A4 2쪽 안에 들어가야 하므로, 다시 쓴 글은 원래 길이의 ±15% 안에 둡니다.
- **농담, 감탄, 유행어를 넣지 않습니다.** 자연스러움은 친근한 표현이 아니라 매끄러운 흐름에서 나옵니다.

## 예시

> 수정 전: 패션 매장에서 고객을 응대하고 상품을 진열했으며, 창고에서 입출고와 재고를 관리했습니다. 소프트웨어 회사에서는 Angular 프런트엔드 개발과 QA를 맡았습니다.
>
> 수정 후: 패션 매장에서는 손님을 맞고 상품을 진열했고, 창고에서는 물건을 들이고 내보내며 재고를 챙겼습니다. 그 전에는 소프트웨어 회사에서 Angular로 웹 화면을 만들고 QA를 맡았습니다.

두 문장이 같은 사실을 담고 있지만, 수정 후에는 "그 전에는"으로 시간 순서가 드러나고 "관리했습니다" 같은 보고서 낱말이 빠졌습니다.

> 수정 전: 지점별 회원 명부와 주간 근무표 작성·공개 기능을 구현했습니다.
>
> 수정 후: 지점마다 회원 명부를 두고, 주간 근무표를 짜서 공개하는 기능을 만들었습니다.

가운뎃점으로 압축한 명사 덩어리("작성·공개 기능")를 동사로 풀었습니다.

## 점검표

- [ ] 다시 쓴 글의 사실이 원본 목록과 정확히 같다. 빠지거나 새로 생긴 사실이 없다.
- [ ] 문단마다 앞뒤 문장이 시간이나 이유로 이어진다.
- [ ] 같은 어미나 같은 동사("개발했습니다")가 세 번 넘게 이어지지 않는다.
- [ ] 기능 설명의 주어가 기능이 아니라 그것을 쓰는 사람이다.
- [ ] 합니다체를 유지했고, 표와 UI 문구는 그대로다.
- [ ] 분량이 원본의 ±15% 안이다.
- [ ] 마지막으로 `korean-writing` 점검표를 통과했다.
