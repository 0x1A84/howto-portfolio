# 한국어 자연스럽게 쓰기

한국어 화자가 직접 쓴 것처럼 읽히는 문장을 씁니다. 영어 문장 구조를 옮긴 번역투, 과장된 수식, AI가 자주 쓰는 틀에 박힌 표현을 걷어 냅니다.

## 작업 순서

1. **문체를 정합니다.** 아래 표에서 글의 종류에 맞는 문체를 고르고, 한 글 안에서 섞지 않습니다.
2. **초안을 씁니다.** 주어와 서술어를 가깝게 두고, 한 문장에는 한 가지 내용만 담습니다.
3. **점검표로 고칩니다.** "고쳐야 할 표현"과 "점검표"를 차례로 적용합니다.
4. **소리 내어 읽듯 다시 봅니다.** 숨이 막히는 긴 문장은 나누고, 같은 어미가 세 번 넘게 이어지면 바꿉니다.

## 문체

| 글의 종류 | 문체 | 예 |
| --- | --- | --- |
| 포트폴리오 본문, 웹 페이지 문구 | 합니다체, 1인칭 주어 생략 | 매장 근무표 기능을 개발했습니다. |
| README, 명세서, CLAUDE.md 같은 문서 | 합니다체 | 인쇄 스타일은 `print.css`에 모읍니다. |
| 표 안의 짧은 항목, 목록의 명사구 | 명사형으로 끝냄, 마침표 없음 | 상품 입출고와 진열 |
| 커밋 메시지 요약 | 현재형 동사 + 명사, 마침표 없음 | 프로젝트 카드에 기술 태그 추가 |
| 버튼, 메뉴 같은 UI 문구 | 짧은 명사구나 동사 원형 | PDF로 저장, A4로 인쇄 |
| 사용자에게 보내는 답변 | 해요체 또는 합니다체 중 대화에서 쓰던 것 | 명세서에 PDF 내보내기를 추가했어요. |

## 고쳐야 할 표현

### 번역투

| 피할 표현 | 바꾼 표현 | 이유 |
| --- | --- | --- |
| 고객 응대를 **통해** 경험을 쌓았습니다 | 고객을 응대하며 경험을 쌓았습니다 | "through"의 직역 |
| 재고 관리**에 있어서** 중요한 것은 | 재고를 관리할 때 중요한 것은 | "in ~ing"의 직역 |
| 세 개의 프로젝트**를 가지고** 있습니다 | 프로젝트가 세 개 있습니다 | "have"의 직역 |
| 개발**되어졌습니다**, 보여**지는** | 개발했습니다, 보이는 | 이중 피동 |
| 그**에 의해** 작성된 문서 | 그가 쓴 문서 | 불필요한 피동 |
| 많은 고객**들** | 많은 고객 | 수량어가 있으면 "들"을 뺌 |
| ~하는 **것이다**, ~할 **것이다** | ~한다, ~하겠다 | 문장마다 "것"으로 끝내지 않음 |
| **~에 대한** 이해**에 대한** 설명 | ~을 이해하는 방법 설명 | "about"의 반복 |
| **하나의** 화면에서 | 한 화면에서 | "a/one"의 직역 |
| 사용자**로 하여금** 확인하게 | 사용자가 확인하도록 | 사역 구문 직역 |
| 이 기능은 **~할 수 있도록 해 줍니다** | 이 기능으로 ~할 수 있습니다 | "enables"의 직역 |

### 군더더기와 과장

- "진행하다", "수행하다", "실시하다"는 구체적인 동사로 바꿉니다. "테스트를 진행했습니다" → "테스트했습니다".
- "~적"을 줄입니다. "효율적인 관리를 위한 체계적 접근" → "재고를 빠짐없이 관리하는 방법".
- "다양한", "혁신적인", "효과적으로", "성공적으로", "적극적으로"처럼 근거 없는 수식어는 지우거나 사실로 바꿉니다. "다양한 고객을 응대했습니다" → "한국어와 영어로 고객을 응대했습니다".
- 같은 뜻을 두 번 쓰지 않습니다. "미리 예약", "가장 최적", "약 10여 개".
- 문장 끝의 "~하고 있습니다"는 실제로 진행 중일 때만 씁니다.

### AI가 쓴 티가 나는 틀

- "~는 단순한 ~가 아닙니다. ~입니다." 같은 대비 구문으로 시작하지 않습니다.
- "결론적으로", "요약하자면", "핵심은 ~입니다"로 문단을 맺지 않습니다. 앞 문단을 되풀이하지 않습니다.
- 목록마다 "**굵은 제목**: 설명" 형태를 반복하지 않습니다. 굵은 글씨는 꼭 필요한 곳에만 씁니다.
- 줄표(—)로 문장을 잇지 않습니다. 쉼표, 쌍점, 또는 문장 나누기로 바꿉니다.
- 항목을 억지로 셋씩 맞추지 않습니다. 있는 만큼만 씁니다.
- 질문을 던지고 스스로 답하는 구성("그렇다면 왜 ~일까요?")을 쓰지 않습니다.

## 표기 규칙

- **띄어쓰기**는 한글 맞춤법을 따릅니다. 의존 명사(수, 것, 데, 만큼)와 단위 명사(개, 명, 쪽)는 띄웁니다. 아라비아 숫자 뒤의 단위는 붙여도 됩니다: `2쪽`, `360px`.
- **외래어**는 국립국어원 외래어 표기법을 따릅니다: 콘텐츠, 프런트엔드, 메시지, 내비게이션, 레이아웃. 고유명사와 기술 이름은 원어로 씁니다: Angular, TypeScript, Playwright.
- **문장 부호**: 문장은 마침표로 끝내고 느낌표는 쓰지 않습니다. 기간은 물결표나 줄표 대신 en dash를 씁니다: `2023–2026`.
- **영어 섞어 쓰기**: 한국어 낱말이 있으면 한국어를 씁니다. "리뷰를 요청" 대신 "검토를 요청", "이슈" 대신 "문제"나 "오류". 업계에서 굳은 말(QA, API, SCM)은 그대로 둡니다.
- **조사**는 영문 약어의 읽는 소리에 맞춥니다: `API를`, `QA를`, `PDF로`, `SCM과`.

## 포트폴리오 문장 기준

- 한 항목은 "무엇을 했는지 → 어떻게 했는지 → 누가 무엇을 할 수 있게 됐는지" 순서로 씁니다.
- 직함이나 역할보다 맡은 일을 동사로 씁니다. "QA 담당" → "출시 전 화면과 API를 테스트했습니다".
- 숫자는 확인된 값만 씁니다. 지어낸 성과 수치, 추천사, 고객사 수는 넣지 않습니다.

예시:

> 수정 전: 다양한 고객들과의 커뮤니케이션을 통해 고객 만족도 향상에 기여하는 역할을 성공적으로 수행하였습니다.
>
> 수정 후: 한국어와 영어로 고객을 응대하고, 찾는 상품의 재고와 사이즈를 확인해 안내했습니다.

## 점검표

글을 넘기기 전에 확인합니다.

- [ ] 한 글 안에서 문체가 하나로 통일되어 있다.
- [ ] "통해", "에 있어서", "가지고 있다", "되어지다", "것이다"가 습관처럼 반복되지 않는다.
- [ ] 근거 없는 수식어(다양한, 혁신적인, 성공적으로)가 없다.
- [ ] 한 문장이 두 줄(약 80자)을 넘으면 나눌 수 있는지 검토했다.
- [ ] 줄표로 이은 문장, 대비 구문 도입, 요약 맺음말이 없다.
- [ ] 외래어 표기와 띄어쓰기를 확인했다.
- [ ] 지어낸 사실이나 수치가 없다.
